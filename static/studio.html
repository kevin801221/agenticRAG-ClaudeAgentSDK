Agentic RAG Studio

這張圖不會被執行。被執行的是右邊那段 policy —— 圖只是幫你把它想清楚。 模型：讀取中… 回主畫面

模組庫

拖到畫布上放一個模組。
從節點右邊的圓點拉到另一個節點，畫一條連線。
連線上的方框可以寫條件（「評分不足」）。
往回連的線會變紅色 —— 那是折返。
選中節點或連線按 Delete 刪掉。

從左邊拖一個模組進來。
或用右上角「從現有架構開始」載入一個現成的來改。

這張圖的意思

把你畫的連線讀成文字。看得懂才表示這張圖真的說清楚了。

policy — 真正會被執行的東西

agent 收到的是這段字，不是那張圖。

試跑一題

不用先存檔。拿現在畫布上這份草稿直接跑，看它到底會不會動、 走的順序跟你畫的一不一樣。

聊出一個架構

講一下你的情境，它會問幾個會影響架構的問題（每個都說明為什麼問）， 然後直接把架構畫到左邊的畫布上。

LLM 供應商

SDK 是去 spawn claude 這支 CLI，所以「用哪個模型」是環境變數的事，不是程式碼的事。 換供應商不用重開服務，也不用改任何一個模組或 policy —— 下面填的 token 只留在記憶體，不會寫進 .env。

外部 MCP server

我們自己那七個模組，本來就是包成一個叫 ragmod 的 MCP server 餵給 SDK 的。 所以接一個別人的 MCP server，跟自己寫一個模組，對編排來說是同一件事 —— mcp__ragmod__search 和 mcp__context7__query-docs 在 policy 裡都只是一個名字。
